The bootstrap admin username is "{{ .Values.secrets.adminUsername }}".
{{- if .Values.secrets.adminPasswordKey }}
Its password comes from Secret "{{ .Values.secrets.existingSecret }}" key "{{ .Values.secrets.adminPasswordKey }}".
If that key is missing, the first boot generates a strong random password instead (see below).
{{- else }}
No admin password key configured: the first boot generates a strong random password once.
{{- end }}
A generated password is never logged. It is written (0600) to /tmp/helixiam-admin-password in the pod that created
the admin (its log names the path); /tmp is an emptyDir, so read it before that pod restarts:
  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "helixiam.fullname" . }} -- cat /tmp/helixiam-admin-password
(with several replicas, exec into the pod whose log says it generated the password), then sign in and change it.
{{- if not .Values.config.trustedProxies }}

WARNING: config.trustedProxies is empty, so HelixIAM ignores every forwarded header. If anything terminates TLS or
proxies in front of it (this chart's ingress, an external load balancer, a Gateway API route, a service mesh), it
sees plain HTTP (the OIDC issuer and redirects become http://) and every request appears to come from that proxy (one
shared sign-in rate-limit bucket, the proxy's address in the audit log). Set config.trustedProxies to the addresses
the proxy connects from (for example the ingress controller's pod CIDR).
{{- end }}
